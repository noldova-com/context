# TypeScript conformance

This directory holds the pinned TypeScript 7.0.2 reference inputs: the
conformance cases, the diagnostics the reference compiler reports for them,
the diagnostic definitions the package's catalog is generated from, and the
standard-library declarations. They are external evidence, not CONTEXT
implementation code; `TYPESCRIPT-COMPATIBILITY.md` owns the intake, the
expected diagnostics, and the reference invocation.

`npm run vendor:typescript -- <version>` writes this intake: it fetches the
pinned upstream sources, replaces every vendored directory, and regenerates
the expected diagnostics. `PROVENANCE.json` records the exact upstream
commits, and each section's source and local roots; it records file counts for
the cases, baselines, definitions, and standard library, and hashes for the
two diagnostic-definition files.
`CERTIFICATION.md` records the verification evidence that the vendored intake
is byte-identical to those pinned sources. `licenses/` holds one unmodified
license and notice set for each upstream source, and `.gitattributes`
preserves upstream bytes.

`cases/` holds the upstream test files as they are, and `baselines/` holds
upstream's own recorded output for them, as evidence. In both, `native/`
identifies what the TypeScript 7 native implementation introduced and
`classic/` the pinned main TypeScript suite used by that release. The cases
are every file from both pinned case roots before applicability
classification, and only `*.errors.txt` baselines are included:
language-service, watch, build, API, JavaScript-emission, symbol,
type-printer, and source-map baselines belong to different compatibility
boundaries and are not part of this intake.

`expected/` is what the pinned compiler reported for every case under the
canonical invocation: `diagnostics.jsonl` holds one record per case in path
order, family by family, and `MANIFEST.json` names the pin, the invocation and
its hash, the splitting rule, the accounting, and the attempts that had to be
repeated. It is generated by `npm run
generate:typescript-expected-diagnostics`, never hand-edited, and regenerated
only when the pin, the invocation, or the splitting rule changes, and by the
intake's certification run, which must reproduce it.

`known-failures.json` is the committed ledger of applicable cases the parser
does not yet match, each with the diagnostics it misses and adds, with its
totals and the hash of the expected diagnostics it was measured against. The
runner, `conformance-cases.test.ts`, registers one test per applicable case: a
case fails when it leaves the reference's answer, a known failure fails when
its difference is not the recorded one or when it now matches, so the ledger
shrinks until the expected diagnostics change. `npm run
generate:typescript-known-failures` rewrites it from a complete comparison
after a build, as `TYPESCRIPT-COMPATIBILITY.md` owns. Run the runner alone
with `npm run test -- category:TypeScriptConformance`.

`diagnostic-definitions/` contains the pinned classic diagnostic definitions and the
TypeScript-Go additions that overlay them by code; `npm run
generate:typescript-diagnostics` regenerates the package's catalog from them,
and the package build verifies the checked-in catalog against them.
`libraries/` contains every `lib*.d.ts` of the exact distribution; the
expected-diagnostics generator mounts them as the reference compiler's default
libraries.
